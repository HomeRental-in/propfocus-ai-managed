QUICK ANSWERS
================================================================================

How to get updates?
  Dev team publishes a new package version. You upgrade in Setup — config is kept.
  Repo changes do NOT update your org automatically.

How to test two-way sync?
  SF → Propfocus: Test Connection + change Lead; Propfocus confirms Platform Event.
  Propfocus → SF: POST to inbound REST with Bearer token; verify Lead or Opportunity
  update + owner bell.

Do we share admin password with Propfocus?
  No. Use a dedicated integration user with Propfocus Integration permission set.

Inbound REST URL in browser?
  No token. POST only with Authorization: Bearer <access_token>.

Install URL:
  https://login.salesforce.com/packaging/installPackage.apexp?p0=04tdL000000kGszQAE

Full setup: SETUP_GUIDE.md

GENERAL
================================================================================

Q: What is Propfocus AI for Salesforce?
A: Managed package connecting Salesforce Leads and Opportunities to Propfocus:
   microsite links, site visits, Buyer Insights iframe, notifications, two-way sync.
   The same panel (propfocusLeadLinkGen) is placed on Lead and Opportunity record pages.

Q: What Salesforce edition do we need?
A: Org must support Apex (Developer, Enterprise, Unlimited, Enterprise sandbox).
   Starter/Essentials/Group often fail. Professional needs Security Review.

Q: Do we need Dev Hub?
A: No — that is packaging for the dev team only. You install from the URL above.

Q: Before install?
A: 1. Confirm Lead (and Opportunity) fields to map  2. Install package
   3. Assign permission sets
   4. Configure Propfocus Config (Org Id + Lead/Opportunity field maps)
   5. Configure External Credential (outbound Client Id/Secret)
   6. CSP Trusted Site  7. Add propfocusLeadLinkGen to Lead and Opportunity pages
   Full steps: SETUP_GUIDE.md or E2E_INSTALLATION.md

Q: Should site visit buttons be on Lead or Opportunity?
A: Both are supported. If your process converts Lead → Opportunity when a site
   visit is confirmed, put the panel on Opportunity for post-conversion work and
   keep Lead for pre-conversion microsite/actions as needed. Configure Opportunity
   field mappings and Site Visit Opportunity Lookup Field in Propfocus Config.

Q: Where do outbound OAuth Client Id and Secret go?
A: Setup -> Named Credentials -> External Credentials -> Propfocus API
   -> Propfocus Principal. NOT in Propfocus Config Custom Metadata.
   Salesforce stores them encrypted; Apex never reads the secret.

Q: Why not store the client secret in Custom Metadata?
A: CMDT is visible to admins, included in metadata exports/change sets,
   and not encrypted. External Credential is the Salesforce-recommended
   pattern for packaged integrations.

================================================================================
PACKAGE UPGRADES
================================================================================

Q: How do we get new features or bug fixes?
A: Dev team publishes a NEW version. You UPGRADE — changes do not appear automatically.

   Your process:
     1. Open new install URL while logged into your org
     2. Click Upgrade (Setup -> Installed Packages -> Upgrade)
     3. Re-test after upgrade

   What is kept: Propfocus Config, permission sets, Lead data, Named Credential,
   External Credential skeleton, CSP, External Credential principal values (post-install).
   What changes: Package code (Apex, LWC, REST API); OAuth CMDT fields removed in
   release after 0.5.0-1 (migrate secrets to External Credential first).

Q: When do we NOT need an upgrade?
A: Field mappings, Organization Id, Embed URL, permission sets, Postman payload fixes.

Q: Upgrade steps (sandbox or production)
A:  1. Dev team shares new install URL + version + release notes
    2. Log in (sandbox: test.salesforce.com; production: login.salesforce.com)
    3. Open install URL -> choose Upgrade
    4. Verify version under Installed Packages
    5. Smoke test: Lead/Opportunity buttons, Test Connection, one inbound POST

Q: Upgrading from a version that stored OAuth in Propfocus Config?
A: Copy OAuth Client Id and Client Secret from Config -> Setup -> External Credentials
   -> Propfocus API -> Propfocus Principal BEFORE upgrading. After upgrade, OAuth CMDT
   fields are removed; auth lives only in the External Credential.

Q: Upgrade not offered?
A: Beta install -> uninstall, install Released version (note External Credential Client Id/Secret first).
   Wrong org -> log out, log into target org, retry.

Q: Upgrade from 0.5.x checklist?
A: See E2E_INSTALLATION.md "Upgrade from 0.5.x". Critical: migrate Client Id/Secret
   into External Credential Principal BEFORE upgrading past OAuth-in-Config builds.

Q: How do we uninstall or roll back?
A: Prefer disable (remove LWC, unassign perm sets, revoke External Client App) over
   uninstall. Before uninstall, note External Credential secrets, Config mappings,
   and JWT Consumer Key. After uninstall, ask Propfocus to disable the Organization Id.
   Full steps: E2E_INSTALLATION.md "Uninstall / rollback".

REPO vs ORG

Q: Do Git repo changes auto-update our org?

Q: Deploy source directly instead of package?
A: Not recommended for production. Use the managed package.

================================================================================
TWO-WAY SYNC
================================================================================

Q: What is the inbound REST URL?
A: https://<your-org-host>/services/apexrest/PropfocusAI/propfocus/events/
   Copy from propfocusAI Admin Setup tab.

Q: How to test SF -> Propfocus?
A: Configure External Credential Client Id/Secret -> Test Connection -> change Lead -> Propfocus confirms event.

Q: How to test Propfocus -> SF?
A: Integration user + Connected App -> POST JSON with Bearer token.
   Resolver matches Lead first, then Opportunity, by buyer_id (or explicit
   salesforce_lead_id / salesforce_opportunity_id). See INBOUND.md.

Q: What identity does outbound site visit / microsite send?
A: Lead panel: salesforce_lead_id. Opportunity panel: salesforce_opportunity_id.
   Both also send buyer_id. See OUTBOUND.md.

Q: What does Test Connection test?
A: Outbound only (OAuth to propfocus.in). Does not test inbound REST. Sandboxes use dev.propfocus.in after override.

================================================================================
SECURITY & PERMISSION SETS
================================================================================

Q: Permission sets included?
A: Propfocus User (sales), Propfocus AI Admin (config), Propfocus Integration (API user).

Q: What does Propfocus need from us?
A: Organization Id, Inbound REST URL, outbound Client Id/Secret (External Credential principal),
   Connected App for inbound. NOT admin username/password.

Q: Sandbox first?
A: Yes — recommended for UAT. Use test.salesforce.com for sandbox installs.

Q: Sales user gets error on Generate Microsite but admin works?
A: Assign Propfocus User permission set. It includes External Credential
   principal access so the running user can authenticate callouts.

================================================================================
TROUBLESHOOTING
================================================================================

Install fails — Apex Classes missing     -> Wrong org edition
Test Connection fails                    -> External Credential Client Id/Secret, Organization Id
Generate Microsite unauthorized          -> Propfocus User + External Credential principal access
Blank iframe                             -> CSP Trusted Site frame-src + hard refresh
History shows dashes                     -> Upgrade to 0.5.0-1+
Opportunity buttons fail                 -> Opportunity Config mappings + buyer id populated
                                           + LWC on Opportunity page
Two-way sync not working                 -> Outbound: Test Connection + event subscription
                                           Inbound: integration user + POST to REST
No Lead/Opportunity for buyer_id         -> Mapped Buyer Id field value on parent record
